# 第18课：多计算节点路由系统

## 学习目标
- 理解`QueryRouter`的自适应负载均衡机制
- 掌握Progress-based动态限额调整
- 理解Memory Node作为消息中继的角色

## 内容大纲

### 1. 多CN拓扑
```
         ┌──────────────┐
         │  Memory Node │  (中继/路由)
         └──┬───┬───┬──┘
            │   │   │
    ┌───────┘   │   └───────┐
    ↓           ↓           ↓
┌────────┐ ┌────────┐ ┌────────┐
│ CN 0   │ │ CN 1   │ │ CN 2   │
│ Router │ │ Router │ │ Router │
└────────┘ └────────┘ └────────┘
```
- Memory Node作为消息中继（不感知查询内容）
- CN之间不直接通信，通过MN转发

### 2. 自适应负载均衡
```cpp
// 每处理完batch_size个查询，同步一次
if (local_slot % batch_size == 0) {
    // 1. 广播当前进度（队列大小）给所有其他CN
    send_batch_acks_with_progress(progress);
    // 2. 等待接收所有其他CN的进度
    while (!received_all_acks()) poll_recv_cq();
    // 3. 更新每CN的限额
    update_limits();
}

// 限额更新公式
void update_limits() {
    denom = Σ(sum_progresses - progresses_[i]);  // 其他CN的总进度
    for each CN i:
        limits_[i] = LIMIT_PER_CN × (sum_progresses - progresses_[i]) / denom × num_cns;
    // 确保总计 = batch_size
}
```
**直觉**: 进度快的CN（队列短）分配更多查询，进度慢的CN（队列长）少分配

### 3. 查询路由
```cpp
// 每个查询的路由决策
idx_t destination = 0;
auto min_placement = placement_.closest_centroids(query);

// 从最近CN开始尝试
while (!min_placement.empty()) {
    destination = min_placement.top().first;
    min_placement.pop();

    if (BALANCED_ROUTING && histogram_[destination] < limits_[destination])
        break;  // 找到可选且未超限额的CN
}

if (destination == cn_id_) {
    query_queue.enqueue(local_slot);  // 本地处理
} else {
    route_query(id, components, destination, random_memory_node);  // 转发
}
```

### 4. 消息格式
```cpp
// 查询消息 (通过MN转发)
[destination_CN(4B) | query_id(4B) | query_vector(dim*4B)]

// ACK消息
[AckHeader | sender_CN(4B) | progress(4B)]

// 终止消息
[termination_header(4B)]
```

### 5. 缓冲区管理
```cpp
// Freelist管理固定大小的消息槽
buffer_entries_ = batch_size × 2 × (qps.size() + 1);
// 两倍于batch_size，每个MN有独立的recv槽

idx_t pop_freelist() {
    idx_t offset = freelist_.back();
    freelist_.pop_back();
    return offset;
}
// 发送完成或接收处理后归还freelist
```

### 6. 终止协议
```
1. CN处理完所有本地查询 → send_batch_acks_with_progress (final)
2. CN → 所有MN: termination_message
3. CN等待: 收到 MN × INITIAL_RECVS 个termination确认
4. 所有CN都发送termination后 → routing完成
```

### 7. 关键常量
```cpp
BALANCED_ROUTING = true;      // 使用histogram限制
ADAPTIVE_ROUTING = true;      // 使用progress动态调整
INITIAL_RECVS = 20;           // 每MN预投递recv数量
LIMIT_PER_CN = 200;           // 每轮每CN最大查询数
MAX_QUEUE_SIZE = 1000;        // 本地队列上限（同步点）
```
