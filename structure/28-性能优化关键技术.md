# 第28课：性能优化关键技术

## 学习目标
- 理解项目中使用的关键性能优化技术
- 掌握协程并发、GPUDirect RDMA、批量RDMA等优化手段
- 学习性能分析方法和优化方向

## 内容大纲

### 1. 协程并发重叠计算与I/O
```
传统同步模型:
  RDMA Read → wait → GPU Compute → wait → RDMA Read → ...

协程模型:
  Coro0: [RDMA] ............. [GPU] ........ [RDMA] ...
  Coro1: .... [GPU] ............... [RDMA] ..... [GPU] ..
  Coro2: ........ [RDMA] ........... [GPU] .............
          ↑ 全部时间被计算或I/O占满 ↑
```
关键参数: `num_coroutines` (默认4)，总吞吐随协程数线性增长直到硬件饱和

### 2. GPUDirect RDMA路径
| 路径 | 延迟(近似) | 带宽 | 使用场景 |
|------|----------|------|---------|
| Host Staging | RDMA→Host + Host→GPU | PCIe×2 | 兼容模式 |
| GPUDirect | RDMA→GPU | PCIe×1 | 高性能 |
| 间接指针 | RDMA→分散GPU地址 | PCIe×1 | 非连续向量 |

适用条件:
- GPU和NIC在同一PCIe root complex
- 或加载了`nvidia-peermem`内核模块
- GPU内存已通过`ibv_reg_mr`注册到RDMA PD

### 3. 批量RDMA减少往返
```cpp
// 非批量: 每个向量一次RDMA往返
for auto& ptr : unvisited:
    node = co_await rdma_read_one(ptr);  // N次往返

// 批量: 所有向量一次提交
auto vecs = co_await batch_read_vectors(unvisited, thread);  // N次提交, 1次等待
```
批量RDMA的关键优势：
- 提交多个RDMA Read后统一等待——流水线化网络延迟
- 减少CQ轮询次数
- 更好的PCIe带宽利用率

### 4. 量化存储减少带宽
```
float32: 128维 × 4B = 512B/向量
uint8:   128维 × 1B = 128B/向量 (节省75% RDMA带宽)
```
收益：
- RDMA读取更快（数据量减少）
- 更多向量可放入GPU计算
- Memory Node存储密度提升

### 5. BFS分区减少跨节点RDMA
```
Balanced分区: 跨shard边比例 ~90%
BFS分区:      跨shard边比例 ~70%
METIS分区:    跨shard边比例 ~50%
```
搜索时跨shard的邻居读取需要额外的RDMA往返到另一个Memory Node

### 6. 异步反向边更新
```
sync模式: 插入等待所有反向更新完成 → 高延迟
async模式: 插入后立即返回，反向更新在后台完成 → 高吞吐
```
`storage_owner_reverse_mode`: async适合批量插入，sync适合需要强一致性的场景

### 7. 关键性能调优参数总结
| 参数 | 含义 | 调优方向 |
|------|------|---------|
| `num_coroutines` | 每线程协程数 | 增大到RDMA/GPU利用率饱和 |
| `beam_width` | 搜索束宽 | 增大提高recall，降低吞吐 |
| `R` | 最大出度 | 增大提高recall，增加存储 |
| `storage_owner_batch_max` | 插入批大小 | 增大提高吞吐，增加延迟 |
| `storage_owner_peer_rdma_tokens` | Peer RDMA并发数 | 增大提高并发，可能溢出 |
