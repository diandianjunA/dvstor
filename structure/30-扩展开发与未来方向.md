# 第30课：扩展开发与未来方向

## 学习目标
- 理解代码的扩展点和设计约束
- 掌握添加新功能的开发模式
- 了解潜在的性能改进方向

## 内容大纲

### 1. 扩展点总览

| 扩展方向 | 涉及文件 | 难度 |
|---------|---------|------|
| 新增距离度量 | `distance.hh`, `compute_service.hh` | 低 |
| 新增向量数据类型 | `vector_dtype.hh`, `gpu_kernel_launcher.cu` | 中 |
| 新增图分区策略 | `partitioning.hh/.cc` | 中 |

### 3. 支持NVMe分层存储
```
当前: 全部索引在Memory Node内存中 (260GB限制)
未来: 热的图结构在内存，冷的向量数据在NVMe

设计思路:
1. Memory Node添加NVMe manager
2. 节点布局新增: is_cold(1b) + nvme_offset(8B)
3. 读取冷向量时: RDMA READ → 检查is_cold → 触发NVMe读取
4. 使用io_uring或SPDK进行异步NVMe I/O
```

### 4. 多GPU支持
```
当前: 1个GPU device
改进: 利用多GPU并行处理

设计思路:
1. GpuBufferManager支持多设备
2. 协程分配到不同的GPU stream
3. 向量batch分配到不同GPU并行计算
4. GPUDirect RDMA到各自的GPU内存

挑战:
- PCIe带宽分配
- NUMA感知的GPU/NIC亲和性
```

### 5. 流式插入优化
```
当前: 插入等待反向边更新完成
改进: 完全异步的管道化插入

设计思路:
1. Phase 1 (Beam Search) 与 Phase 5 (反向更新) 流水线化
2. 使用lock-free结构管理pending updates
3. 批量合并同一节点的多个反向更新
4. 利用WAL(Write-Ahead Log)保证crash consistency
```

### 6. 自适应参数调优
```
当前: R, beam_width, alpha 等参数固定
改进: 根据数据分布动态调整

设计思路:
1. 在线监测recall和延迟
2. 高recall区域: 减小beam_width
3. 低recall区域: 增大beam_width
4. 根据节点局部密度调整R
```

### 7. 高级图维护
```
周期性维护:
- 删除已过时的向量
- 全局re-prune优化图质量
- 增量medoid重选（图中心偏移时）
- 添加"长边"改善搜索跳数
```

### 8. 安全与容错
```
当前: 无持久化WAL
改进:
- RDMA传输加密（TLS over TCP for control, 硬件加密for data）
- Checkpoint机制定期保存图状态
- 脑裂防护（lease机制）
- 优雅降级（某个MN故障时的搜索fallback）
```

### 10. 贡献指南
- 遵循现有代码风格（2空格缩进，PascalCase类型，snake_case函数）
- 添加对新参数/枚举值的验证
- 性能关键路径添加breakdown统计
- 提交: 简洁的英文subject，描述修改的子系统
