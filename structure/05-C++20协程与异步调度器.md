struct VamanaCoroutine {
    // initial_suspend = suspend_always  → 手动控制恢复时机

### 3. RDMA异步等待模式
```cpp
// 在 vamana_rdma_reads.hh 中
inline auto read_vamana_node(RemotePtr rptr, thread) {
    // 1. 分配本地缓冲区
    byte_t* node_ptr = thread->buffer_allocator.allocate_buffer(read_size);
    // 2. 提交RDMA读请求
    qp->post_send(local_addr, size, lkey, IBV_WR_RDMA_READ, ...);
    thread->track_post();  // 记录一个未完成的RDMA操作
    // 3. 返回awaitable（协程在此挂起）
    return awaitable{rptr, node_ptr, read_size, thread};
}
// 协程恢复时: scheduler检查post_balances==0后调用await_resume()
```

### 4. 调度器核心循环 (`src/vamana/scheduler.hh`)
```cpp
template <class Distance, bool insert>
void schedule(Vamana<Distance>& vamana_idx, ...) {
    for (;;) {
        bool all_done = true;
        for (u32 coroutine_id = 0; ...; ++coroutine_id) {
            // 1. 轮询RDMA完成
            thread->poll_cq();
            // 2. 轮询GPU完成
            thread->poll_gpu_events();
            // 3. 回收已完成协程，分配新任务
            if (coroutine.handle.done()) { /* 分配新查询/插入 */ }
            // 4. 恢复就绪协程 (RDMA+GPU都完成)
            else if (thread->is_ready(coroutine_id)) {
                coroutine.handle.resume();
            }
        }
        if (all_done) break;
    }
}
```

### 5. 同步机制
- **post_balances**: 每个协程一个原子计数器，跟踪未完成的RDMA操作
- **gpu_post_balances**: 每个协程一个原子计数器，跟踪未完成的GPU操作
- **is_ready()**: `post_balances[id] == 0 && gpu_post_balances[id] == 0`
- WR ID编码: `encode_64bit(thread_offset, coroutine_id)` 用于完成回调

### 6. 计算vs I/O重叠
协程的核心价值：当一个协程等待RDMA/GPU完成时，调度器可以处理其他协程：
```
时间线: Coroutine A: [RDMA read...]   [GPU compute...]
        Coroutine B:   [GPU compute...]  [RDMA read...]
        Coroutine C:     [RDMA read...]    [GPU comp...]
→ CPU持续忙碌，RDMA和GPU利用率最大化
```
