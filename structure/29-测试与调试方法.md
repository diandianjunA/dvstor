### 5. 常见问题排查

#### 问题: RDMA连接失败
```
检查: 
1. ibv_devinfo — RDMA设备是否正常
2. rdma-library/library/utils.cc — IP映射是否正确
3. 防火墙: TCP端口 + RDMA端口
4. /etc/hosts 或 DNS解析
```

#### 问题: GPU kernel失败
```
检查:
1. nvidia-smi — GPU是否可用
2. cuda-memcheck — 内存访问错误
3. CMAKE_CUDA_ARCHITECTURES — 是否匹配GPU
4. GPUDirect: nvidia-smi topo -m — GPU与NIC拓扑
```

#### 问题: 大页分配失败
```
解决:
1. echo 1024 > /proc/sys/vm/nr_hugepages
2. 或编译时: 移除 -DNOHUGEPAGES
3. 检查: cat /proc/meminfo | grep Huge
```

#### 问题: 内存不足
```
症状: "out of local memory" 或 "out of memory"
解决:
1. 增大 --cn-memory 或 --mn-memory
2. 检查内存泄漏: valgrind --leak-check=full
3. 检查BufferAllocator: allocated_memory() 返回值
```

### 6. 性能分析工具
```
CPU:          perf record / perf report
GPU:          nvprof / nsys profile
内存:         heaptrack / massif
RDMA:         perftest (ib_write_bw, ib_read_bw)
协程:         添加debug stat打印coroutine状态
网络:         tcpdump + 分析RDMA包
```

### 7. Breakdown分析流程
```bash
# 1. 启用breakdown
./build/dvstor_breakdown_benchmark \
    --service-config config.ini \
    --workload mixed \
    --output-dir ./reports/

# 2. 分析报告
cat reports/breakdown/*.txt
# 查看各Subcategory的p50/p95/p99延迟

# 3. 定位瓶颈
# 如果 rdma_vector_fetch > 50% → 考虑量化/GPUDirect
# 如果 gpu_query_distance > 20% → 考虑减小beam_width
# 如果 cpu_query_beam_update > 15% → 考虑优化数据结构
```
