# 方案一动机实验结果分析报告

## 1. 实验概况

- 结果目录：`program1_20260823_111256`
- 数据集：SIFT100M，128 维 uint8 向量
- 索引：schema 16，baseline、solution 和 quality 使用相同索引指纹 `68737734120060260`
- Baseline：`coupled`，返回 ACK 前同步完成全局搜索和图维护
- 方案一：`decoupled`，本地 Stage1 完成后返回 ACK，由 Stage2 异步完成全局完善
- 性能负载：insert-only，16 个客户端线程，预热 128 次，正式测量 1000 次
- 质量负载：插入 1000 个新节点，并查询全部 1000 个新向量
- 重复次数：1

本轮新增了基于真实 RDMA 提交、传输资源等待和 CQ 完成边界的关键路径计时。旧的 `remote_dependency_ns` 只覆盖部分函数，不能作为完整 RDMA 开销；本报告使用新的 `rdma_wait_ns`。

## 2. 核心结论

1. **RDMA 路径占同步插入关键路径的 80.81%。** 每次插入平均耗时 46.46 ms，其中 RDMA 提交、背压及完成等待为 37.55 ms，其余 CPU、本地处理和协议时间为 8.92 ms。RDMA 是同步更新性能差的主导因素。
2. **86.49% 的同步关键路径可以推迟到 Stage2。** 全局 continuation、最终候选快照和远程反向边维护合计 40.19 ms。RDMA 比例与可推迟工作比例相互印证：可推迟阶段主要由跨分片 RDMA 驱动，同时包含少量 CPU 搜索和图处理。
3. **方案一将前台插入吞吐提高 6.56 倍。** 吞吐从 337.65 ops/s 提升到 2216.18 ops/s；平均 ACK 延迟下降 84.80%，P99 下降 92.67%。即使把 Stage2 排空时间计入，durable 吞吐仍提升 5.41 倍。
4. **Stage1-only 的整体查询结果接近最终状态。** Stage1 和 Stage2 完成后的 Top-10 结果重合率为 97.26%，平均每个查询只有约 0.274 个结果发生变化。严格的新节点 self-hit@10 为 86.5%，最终达到 100%。
5. **临时状态通常只持续百毫秒量级。** Stage2 平均完成延迟为 121.89 ms，P99 所在直方图区间的上界为 512 ms；所有任务最终完成，无 backlog 和失败。
6. **迁移改善了动态节点的物理局部性。** 跨分片边比例由 17.93% 降至 14.30%，相对下降 20.26%，而实际迁移的节点仅占 10.46%。

## 3. 实验一：插入过程中的 RDMA 开销

### 3.1 新的准确计时结果

| 开销类型 | 每次插入平均时间 | 占同步插入关键路径比例 |
| --- | ---: | ---: |
| RDMA 路径 | **37.55 ms** | **80.81%** |
| CPU、本地处理与其余协议 | 8.92 ms | 19.19% |
| **总计** | **46.46 ms** | **100%** |

这里的 RDMA 路径统计以下互斥的墙钟区间：

- 同步 RDMA Read、Write、CAS 和 FAA 从发起到完成；
- 批量异步 RDMA 从传输资源申请和提交开始，到该批全部 CQE 被观察到；
- 多个并行 WQE 只统计一次批次等待区间，不按 WQE 累加；
- CQE 到达后的候选解析、距离计算和剪枝不计入 RDMA。

因此，80.81% 表示前台插入因 RDMA 调用而占用的关键路径时间，而不是把整个远程处理函数笼统地算作网络时间。剩余的 19.19% 是总关键路径减去这些无重叠 RDMA 区间，包含 CPU 计算、本地内存操作及控制协议。

### 3.2 与可推迟 Stage2 工作的交叉验证

| 关键路径部分 | 平均时间 | 占比 |
| --- | ---: | ---: |
| 本地 Stage1 搜索 | 5.91 ms | 12.73% |
| 跨分片全局 continuation | 31.95 ms | 68.76% |
| 最终候选快照 | 0.25 ms | 0.55% |
| 远程反向边维护 | 7.99 ms | 17.19% |
| 最终 prune | 0.18 ms | 0.38% |
| 节点分配与写入 | 0.10 ms | 0.22% |
| 元数据及其他 | 0.08 ms | 0.17% |
| **合计** | **46.46 ms** | **100%** |

方案一推迟的三项为：

```text
全局 continuation       31.95 ms
+ 最终候选快照           0.25 ms
+ 远程反向边维护         7.99 ms
= 可推迟工作            40.19 ms，占 86.49%
```

RDMA 路径为 37.55 ms，可推迟工作为 40.19 ms，两者相差 2.64 ms。该差值主要是全局搜索和图维护中的 CPU 评分、控制与数据处理。这说明 Stage2 不是单纯延迟网络传输，而是将一个以 RDMA 为主、同时包含少量 CPU 工作的全局后缀整体移出 ACK 路径。

### 3.3 旧的 24.66% 为什么不能使用

旧字段仍显示：

```text
remote_read + remote_reverse = 11.46 ms，占 24.66%
```

该字段只覆盖部分旧函数计时，没有覆盖 global continuation 内的批量远程向量和邻接读取；同时 `remote_reverse` 又包含部分 CPU 操作。因此它既不是完整 RDMA 时间，也不是纯网络时间。论文图应使用新的 80.81%，不要再使用 24.66%。

### 3.4 动机是否得到支持

得到直接支持。最合适的论文表述是：

> In the coupled design, RDMA submission, backpressure, and completion waiting account for 80.8% of the insertion critical path. Our design acknowledges an insertion after local Stage1 and moves the RDMA-dominated global completion to asynchronous Stage2.

中文可表述为：

> 同步设计中，RDMA 提交、传输背压与完成等待占插入关键路径的 80.8%。方案一在本地 Stage1 后立即确认插入，将 RDMA 主导的全局完善过程推迟到异步 Stage2。

## 4. 实验二：方案一的更新性能

| 指标 | Coupled baseline | Two-stage | 改善 |
| --- | ---: | ---: | ---: |
| 前台插入吞吐 | 337.65 ops/s | 2216.18 ops/s | **6.56×** |
| 含 Stage2 drain 的 durable 吞吐 | 337.65 ops/s | 1827.63 ops/s | **5.41×** |
| 平均 ACK 延迟 | 46.76 ms | 7.11 ms | **下降 84.80%** |
| P50 ACK 延迟 | 22.52 ms | 5.87 ms | 下降 73.92% |
| P95 ACK 延迟 | 181.30 ms | 16.03 ms | 下降 91.16% |
| P99 ACK 延迟 | 296.84 ms | 21.76 ms | **下降 92.67%** |
| P99.9 ACK 延迟 | 369.23 ms | 23.78 ms | 下降 93.56% |

客户端观测的 baseline 平均延迟为 46.76 ms，与存储侧测得的 46.46 ms 关键路径仅相差约 0.30 ms，说明存储侧计时与端到端结果一致。

移除 RDMA 路径后，baseline 关键路径理论剩余 8.92 ms；方案一实际平均 ACK 延迟为 7.11 ms。两者量级吻合，差异来自方案一的 Stage1 实现、执行批次和前后台协议不同。这进一步说明吞吐提升主要来自将 RDMA 主导的后缀移出前台。

建议论文同时报告：

- **6.56× foreground throughput**：用户可见的 Stage1 ACK 吞吐；
- **5.41× durable throughput**：包含测量结束后 Stage2 排空时间的保守吞吐。

## 5. 实验三：Stage1-only 短期质量

| 指标 | Stage1-only | Stage2 完成后 | 差异 |
| --- | ---: | ---: | ---: |
| 新节点 self-hit@10 | 86.5% | 100% | 下降 13.5 个百分点 |
| 与最终 Top-10 的结果重合率 | 97.26% | 100% 参考 | 仅 2.74% 结果变化 |
| 查询数 | 1000 | 1000 | — |

有效性检查：

- 人工 Stage2 延迟为 15 s；
- 插入及 Stage1-only 查询在 2.706 s 内完成，确实位于 Stage1-only 窗口；
- 最终查询前，5 个分片的 durable sequence 均达到目标；
- `stage2_finalization.complete = true`；
- 1000 次插入全部成功。

1000 个查询并不算过少。Stage1 self-hit 86.5% 的 Wilson 95% 区间约为 84.24%–88.48%，最终 100% 的区间约为 99.62%–100%。这足以说明结果量级，但最终论文仍可通过重复实验给出跨运行误差。

两个质量指标需要分开解释：

- self-hit@10 是严格的新节点可达性压力测试，Stage1 期间仍有 13.5% 的新节点无法检索到自身；
- Top-10 overlap 衡量整体结果稳定性，97.26% 意味着平均每个查询的 10 个结果中有 9.726 个与最终结果相同。

推荐结论：Stage1 并非已经达到最终质量，但整体结果变化较小，并且这种差异只存在于较短的异步完善窗口内。该实验不是基于动态 exact ground truth 的标准 Recall@10，论文中不能把 self-hit 或 overlap 直接写成 Recall@10。

## 6. 实验四：Stage2 临时窗口

| 指标 | 结果 |
| --- | ---: |
| Stage2 完成样本数 | 1128 |
| 平均完成延迟 | **121.89 ms** |
| P99 延迟直方图区间上界 | **512 ms** |
| 测量结束后的 backlog drain | 95.93 ms |
| 最终 remaining | 0 |
| Terminal failures | 0 |
| Peer reverse retries | 0 |
| 最大观测 backlog | 9 |

1128 个样本包括 128 个预热更新和 1000 个正式更新。P99 的 512 ms 是直方图区间上界，不是精确点估计。可以严谨表述为：

> Stage2 completes in 121.9 ms on average, and 99% of samples fall within the histogram bucket bounded by 512 ms, with no terminal failure.

因此，Stage1-only 质量差异通常持续约百毫秒，而不是秒级或分钟级。

| 绝对下降 | — | **3.63 个百分点** |
| 相对下降 | — | **20.26%** |

其他数据：

- 完成 Stage2 的节点：1128；
- 发生物理迁移的节点：118，占 10.46%；
- home match rate：89.54%；
- Stage2 failures：0。

只有约一成节点发生迁移，却减少了 2046 条跨分片边，说明迁移是针对 home 不匹配节点的选择性修复，而不是无差别搬运。

该 locality 统计针对本轮动态节点的最终邻边，不代表整个 SIFT100M 静态基图的全图比例。

## 10. 局限性

1. 性能对照目前只运行一次。正式论文建议至少运行 3 次并报告均值和误差条。
2. `rdma_wait_ns` 是 RDMA 调用占据关键路径的墙钟时间，包含提交和传输背压，不等同于网卡纯线上传播时间；这一口径恰好对应同步插入实际被 RDMA 阻塞的时间。
3. CPU 部分由总关键路径减去无重叠 RDMA 区间得到，表示非 RDMA 路径时间，不是硬件性能计数器测得的 CPU cycles。
4. 质量指标是 self-hit 和相对 Top-10 overlap，不是动态 exact ground truth Recall@10。
5. P99 Stage2 延迟来自离散直方图，只能报告区间上界。
6. Locality 是本轮动态节点的边级统计，不是整个索引的全图扫描结果。
7. 两个性能 JSON 的 `system_variant.label` 都沿用了 profile 默认值 `baseline`；实际模式应以 `resolved_modes.storage_owner_update_completion_mode` 为准，分别为 `coupled` 和 `decoupled`。
